# Kavora v0.1.0

## Evidence-driven local inference control plane

Kavora v0.1.0 is prepared around one operating loop:

```text
Observe -> Validate Evidence -> Predict -> Decide -> Execute -> Verify Outcome -> Calibrate / Roll Back
```

### Four release highlights

1. **Evidence semantics:** cache and backend observations distinguish freshness from `strict`, `estimated`, `fallback`, and `missing` semantic fidelity.
2. **Safe operating envelope:** capacity sweeps automatically recommend a cache threshold and concurrency using SLO feasibility, RPS lower bounds, instability, and evidence uncertainty.
3. **Pre-deployment proof:** anonymous workload signatures compare baseline and candidate policies before a human-approved canary.
4. **Outcome audit:** durable decision/outcome journals measure realized TTFT error and evidence-fidelity drift after execution.

### Reproduce

```bash
make test
make build
make benchmark-fidelity
build/kavora replay benchmark/workload_trace.example.jsonl --policy candidate --evidence-quality strict
```

### Evidence boundary

This release proves the control-plane workflow and deterministic replay semantics. A reviewed real-GPU Stage 2 evidence manifest is frozen in [`v0.1.0-evidence.json`](v0.1.0-evidence.json), and the full bundle is intended as a GitHub Release asset. Measurements remain specific to the exact hardware, model, configuration, and workload manifest; they are not generalized latency or throughput claims.

Stage 7 causal tooling and Stage 8 goodput semantics are implemented. Real randomized online policy effects, held-out predictor generalization, and GPU-resource operating-point recommendations remain evidence-gated until their corresponding artifacts are attached.
