# Kavora 阶段性目标与验收标准

## 推进原则

三个阶段依次服务于求职展示、真实可用和研究实验目标。每个阶段都必须形成可单独运行、测试和演示的闭环；后续阶段只能建立在前一阶段的稳定接口上。

## 阶段一：可展示的双语言智能网关

### 目标

完成 Go LLM Gateway 与 Rust Policy Engine 的最小生产化闭环，证明两种语言在请求热路径上具有清晰、必要且可观测的协作关系。

### 范围

- Go 提供 OpenAI-compatible chat completions 接口；
- 支持普通响应和 SSE 流式响应；
- 接入本地 vLLM 与 SGLang，支持健康检查和故障转移；
- 提供基础租户、API Key、并发限制和 Token 配额；
- Rust 提供 PII 扫描、内容规则、JSON 增量解析、Token 预算和 cache key；
- 使用 protobuf + gRPC，默认通过 Unix Domain Socket 部署；
- 传播 request ID、trace、deadline、cancellation 和结构化错误；
- 暴露 Go/Rust 两侧 Prometheus 指标和 OpenTelemetry trace。

### 必做演示

1. 正常请求经过 Go 和 Rust 后流式返回；
2. 包含敏感信息的请求被 Rust 策略拒绝，并显示策略原因；
3. 输出超过 Token 预算时中止流，并保留完整审计状态；
4. 主推理后端不可用时自动切换到备用后端；
5. trace 中可看到网关、策略引擎和推理后端的完整时序。

### 性能验收

- 提供直连后端与经过网关的 p50/p95/p99 延迟对比；
- 分离 Go 转发、跨进程 RPC、Rust 策略扫描的开销；
- 证明流式慢客户端场景下内存保持有界；
- 对策略引擎不可用、超时和重启进行故障注入。

### 阶段完成定义

- 一条命令启动网关、策略引擎、exporter 和至少一个本地后端；
- Go、Rust 均有单元测试、契约测试和端到端测试；
- README 包含 30 秒演示路径、架构图和“为什么使用两种语言”；
- benchmark 结果可由固定配置复现，而不是只保留截图。

## 阶段二：真实可用的 KV-aware 推理控制面

### 目标

将当前 KV Cache Exporter 的指标与实验能力接入在线路由闭环，使项目能够长期管理多后端推理流量，同时保持决策可解释和可回退。

### 范围

- 将 vLLM/SGLang 指标归一化为稳定的 backend state；
- 使用 prefix/cache key 将潜在复用请求映射到候选后端；
- 综合 KV cache 命中、剩余容量、队列、首 Token 延迟和错误率评分；
- 提供 `static`、`shadow`、`advisory`、`enforced` 四种策略模式；
- 每次路由记录候选集合、输入信号、策略版本、得分和选择原因；
- 增加策略冷却、迟滞、数据缺失降级和快速回退机制；
- 保留现有 Python benchmark/planner 作为离线验证与报告基线。

### 必做演示

1. 相同长前缀请求优先进入有复用价值的后端；
2. KV 压力升高时，路由避免继续压入风险后端；
3. 指标缺失或陈旧时自动退回静态负载均衡；
4. shadow 模式展示“建议路由”和“实际路由”的差异；
5. 管理接口能够解释单个请求的路由决策。

### 实用性验收

- 本地连续运行并具有健康检查、配置热加载和状态恢复；
- 后端新增、下线和故障不会要求重启整个控制面；
- 租户配额、路由策略和 fail-open/fail-closed 可配置；
- 指标语义继续区分 `0.0`、缺失、陈旧和混合质量；
- 所有在线策略均有静态回退路径。

### 阶段完成定义

- 在固定 workload 下比较 static 与 KV-aware 路由；
- 报告吞吐、TTFT、p95/p99、错误率、KV 命中与策略切换次数；
- 只有统计与重复实验支持时才声明性能收益；
- 若无稳定收益，也要形成明确的适用边界或负结果。

## 阶段三：研究实验平台与安全 Agent 扩展

### 目标

在稳定网关和策略控制面的基础上加入安全 Agent 工具执行，并把整个系统升级为可确定性重放、可比较策略和可形成研究结论的实验平台。

### 范围

- Go 实现轻量 Agent loop、工具注册、任务状态、重试和取消；
- Rust 使用 Wasmtime 执行受限工具；
- 工具 manifest 声明文件、网络、时间、内存和 CPU 权限；
- 复用阶段一的租户、策略、Token 预算、trace 和审计；
- 记录模型输出、工具输入、策略版本、路由决策和外部响应摘要；
- 支持不再次调用模型的执行重放；
- 建立固定数据集、负载生成器、实验 manifest 和结果校验器。

### 必做演示

1. Agent 调用 Rust WASM 工具完成一个受控任务；
2. 越权文件或网络访问被拒绝；
3. 工具超时或内存超限不会拖垮 Go 网关；
4. 相同执行记录可以离线重放并定位差异；
5. Agent 请求仍能使用 KV-aware 路由和统一 Token 预算。

### 研究验收

- 比较静态路由、负载路由、KV-aware 路由及其消融；
- 比较无策略、同步策略、流式增量策略的性能和安全覆盖；
- 记录环境、模型、后端版本、随机种子和配置哈希；
- 自动生成机器可读结果和人类可读报告；
- 严格区分功能实现、冒烟验证、单机证据与可推广结论。

### 阶段完成定义

- 形成可重复执行的实验矩阵和基准报告；
- 至少有一个明确的正向机制结果或可信的适用边界；
- Agent 执行安全模型、路由机制和失败语义均有设计文档；
- 项目可以作为 AI Infra 工程作品，也可以支持后续研究写作。

## 跨阶段里程碑

| 里程碑 | 交付物 | 主要价值 |
|---|---|---|
| M1 | Go 网关直连 vLLM/SGLang | 建立请求主链路 |
| M2 | Rust Policy Engine + gRPC/UDS | 展示真实双语言协作 |
| M3 | 流式策略、背压、故障注入 | 展示性能与可靠性工程 |
| M4 | KV-aware shadow routing | 将现有仓库能力接入在线系统 |
| M5 | enforced routing + 可解释决策 | 达到长期可用状态 |
| M6 | 可复现实验矩阵 | 达到研究实验目标 |
| M7 | Rust WASM Agent Runtime | 完成 Agent 扩展 |
